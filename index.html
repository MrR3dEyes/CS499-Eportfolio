Professional Self-Assessment

My career plans have stayed the same since I graduated high school; they have become more specific as I have gone through the Computer Science program here at SNHU. When I finished high school, I wanted to be a game developer or a software developer. As I have grown and learned through these courses, especially with graphics and visualization, I have focused more on programming, game development, technical art, and visual systems. I still enjoy working on hardware as well as troubleshooting, especially since that is my current job as a service and diagnostic technician. My long-term goal is to be more focused on the creative and technical side of software.

Going through the Computer Science program has helped me understand that computer science is not just about getting code to run. It is about writing code that is organized, maintainable, useful, secure, and easier to improve later. My coursework has helped me build skills in software engineering, algorithms, data structures, databases, security, and full-stack development. These areas all connect together because real projects require more than one skill. A project needs to work but also needs to be understandable, stable, and useful for the user or serve a purpose.

One of the biggest things I have learned is how important communication is in computer science. The code review helped me explain what my original project did, the issues I found, and what improvements I planned to make. The milestone narratives and journals also helped me explain not only what I changed but why those changes mattered. This matters in a professional setting because developers need to explain their work to teammates, managers, instructors, and maybe people who will not understand every technical detail. Being able to communicate those choices clearly is something I have improved throughout this course.

My ePortfolio focuses on my CS 330 Computational Graphics and Visualization OpenGL scene project. I chose this artifact because it connects heavily with my career goals in graphics programming, game development, and becoming a technical artist. The project is not just a basic program that displays something. It is a visual project in which code controls what appears on screen. The scene has two vehicles, a lamp post, a sky background, a tree, a grass island, textures, lighting, materials, and camera interaction. This makes it a strong artifact as it shows both visual and technical problem-solving.

For the Software Design and Engineering enhancement, I improved the project by making my code cleaner, more portable, and easier to maintain. I fixed issues with textures, improved material lookup logic, added relative texture paths, added a helper function for loading scene textures, added texture slot checks, removed duplicate mesh loading, and added named constants. These changes may not completely change what the user sees visually, but they have improved how the project works behind the scenes. This showed me that meaningful software improvements do not always have to be huge new features. Fixing bugs, reducing repeated code, improving portability, and making the project easier to maintain can be just as important.

For the Algorithms and Data Structures enhancement, I improved how the static scene objects were organized and rendered. I added a MeshType enum, a scene object struct, a sceneObjects vector, BuildSceneObjectList, and RenderSceneObject. Static scene objects are now stored in a vector and rendered through a loop instead of being handled through repeated hardcoded function calls. I kept the vehicle rendering functions separate because each car is made from multiple pieces with different transformations, textures, and materials. Trying to force the vehicles into one simple scene object would have made the project more complicated instead of cleaner. This helped me understand that algorithms and data structures are not only about sorting or searching. They can also be used to organize real project data and make software easier to expand later.

For the Databases enhancement, I moved static scene object data into a structured CSV file called SceneObjects.csv. The CSV file works as a flat-file database where each row represents one scene object, and each column stores a specific field for that object. These fields include information such as mesh type, scale, rotation, position, texture tag, material tag, color, and UV scale. I also added a loader that reads the CSV file at runtime, validates the data, creates scene objects, and uses a fallback list if the CSV file cannot be loaded. This showed me that database concepts can apply to more than traditional web applications or business systems. I felt very proud applying these concepts to a graphics project because the scene still looks the same, but the objects are stored and loaded better.

The security mindset outcome also connects to my enhancements. In the Software Design and Engineering enhancement, I improved error handling and reduced issues with missing or invalid data causing silent problems. For the Databases enhancement, the CSV loader validates data before using it and falls back to default scene objects if the file is missing or has issues. This helped me understand that software should not only work when everything goes correctly. It should also handle problems in a predictable way and give useful warnings instead of failing unexpectedly.

My work experience has also helped shape how I view computer science. As a service and diagnostic technician, I work with hardware, troubleshooting, system issues, and customer problems. This has helped me develop a practical mindset when working on technical problems. I have learned that it is important to break problems down, test changes, and understand why something is not working rather than just trying random fixes. Whether I am diagnosing a computer issue or improving an OpenGL project, the process still involves identifying the problem, testing possible solutions, and making the final result more reliable.

Overall, this ePortfolio shows my growth as a computer science student and as someone who is heavily interested in technical art, graphics programming, and game development. I want my ePortfolio to show more than just programming assignments. I want it to show that I can build visual technical projects, review my work, make design choices, improve existing code, and explain those improvements. The three enhancements all build on the same OpenGL scene, but each one shows a different area of computer science. Together, they demonstrate software design, engineering, algorithms and data structures, database organization, professional communication, and a strong security-based mindset. This portfolio represents the type of work I want to continue building after graduation, which is work that is both visual and technical, where code directly affects the user's experience.
